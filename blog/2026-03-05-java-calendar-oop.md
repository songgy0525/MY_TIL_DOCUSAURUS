## 1. 메소드형 달력 로직 완성

달력 출력의 핵심 전제: **1일의 요일**과 **해당 월 최대 일수**.

- 월 인덱스: 사용자 입력은 1부터 → 배열 인덱스는 `month - 1`로 보정 필수
- 줄바꿈 규칙: `(첫 요일 공백 + 출력한 일수) % 7 == 0`이면 줄바꿈
- 이전 달 날짜: `month == 1`이면 전달은 12월(31일 고정) 처리 — `0월` 계산 방지

:::warning
`+1` 오프셋 누락 시 이전 달 시작 날짜가 어긋나는 off-by-one 오류 발생 주의.

테스트 케이스: 4년 2월(29일), 5년 2월(28일)로 윤년/평년 검증.
:::

**핵심 키워드:** `윤년` `인덱스-1` `printf` `모듈로7` `이전/이후달력`

## 2. API 선정 기준과 Calendar / LocalDate

| 구분 | Calendar | LocalDate |
|------|----------|-----------|
| 월 입력 | 0부터 시작 → `-1/+1` 반복 필요 | 1부터 시작, 직관적 |
| 객체 생성 | `Calendar.getInstance()` | `LocalDate.of(year, month, 1)` |
| 최대 일수 | `getActualMaximum(Calendar.DAY_OF_MONTH)` | `lengthOfMonth()` |
| 이전 달 | 월에 음수 입력 시 자동 보정 | `minusMonths(1)` |
| 권장 버전 | 호환성 필요 시 | Java 8 이상 권장 |

:::info
API 선정 기준: **많이 사용되는가(호환성)** + **취약점이 적은가(보안/유지보수)**

Eclipse 리팩터링 단축키: `Alt + Shift + R` — 메소드/변수 이름 연관 사용처까지 일괄 변경
:::

**핵심 키워드:** `API선정기준` `Calendar.getInstance` `getActualMaximum` `LocalDate.of` `lengthOfMonth`

## 3. 오버로딩 vs 오버라이딩 vs 하이딩

| 구분 | 조건 | 동작 |
|------|------|------|
| 오버로딩 | 같은 클래스, 같은 메소드명, 다른 인자 시그니처 | 컴파일 타임에 선택 |
| 오버라이딩 | 상속 관계, 동일 시그니처 | 런타임에 자식 구현 실행 (VMI) |
| static 하이딩 | 동일 시그니처의 static 메소드를 자식에 선언 | 오버라이딩 아님, 클래스 기준 호출 |
| 필드 하이딩 | 자식이 부모와 같은 이름의 필드 선언 | 참조 타입 기준으로 결정 |

:::info
오버로딩 성립 조건: **아규먼트 시그니처(개수/타입)만**으로 구분.

접근 제한자, 반환 타입, static 여부는 오버로딩 성립과 무관.
:::

**핵심 키워드:** `오버로딩` `오버라이딩` `static하이딩` `필드하이딩` `업캐스팅`

## 4. VMI와 참조 타입의 멤버 노출

| 구분 | 결정 기준 |
|------|----------|
| 접근 가능한 멤버 (노출) | **참조 변수의 타입** |
| 오버라이딩된 메소드 실행 | **실제 생성된 객체 타입** (VMI) |
| 필드 접근 | 참조 변수의 타입 (하이딩) |
| static 메소드 실행 | 클래스 기준 (하이딩) |

```java
Parent p = new Child();
p.parentMake();
// 선언은 Parent에 있지만 실행은 Child의 재정의 메소드
```

:::info
**상속 관계가 없는 참조 타입끼리는 형변환 불가**.

참조형 형변환의 전제 조건은 상속 관계.
:::

**핵심 키워드:** `VMI` `참조타입` `실제타입` `다형성` `형변환전제`

## 5. this / super와 생성자

| 키워드 | 용도 |
|--------|------|
| `this.필드` | 로컬 변수와 멤버 필드 이름 충돌 시 멤버 명시 |
| `this()` | 같은 클래스 내 다른 생성자 호출 (생성자 체이닝) |
| `super()` | 부모 생성자 호출 — 부모에 기본 생성자 없으면 명시 필수 |
| `super.멤버` | 자식 내부에서 부모 멤버 참조 |

:::warning
외부 코드에서 인스턴스를 통해 부모 멤버를 직접 지정 호출하는 것은 불가능.

부모 동작을 함께 수행하려면 자식 메소드 내부에서 `super.method()` 호출 필요.
:::

**핵심 키워드:** `this()` `this.필드` `super()` `super.멤버` `부모호출제한`

## 6. 인터페이스 구성, 구현, 네스티드

| 구분 | 인터페이스 | 추상 클래스 |
|------|-----------|------------|
| 생성자 | 없음 | 있음 |
| 필드 | 자동 `public static final` | 일반 클래스 규칙 적용 |
| 구현 강제 | `implements` — 미구현 메소드 반드시 오버라이딩 | `extends` — 동일 |
| 다중 상속 | 가능 (`extends A, B`) | 불가 |

```java
// Java 8 이후 인터페이스 확장
default void defaultMethod() { ... }    // 공통 구현 배포
static void staticMethod() { ... }      // 유틸리티
private void helperMethod() { ... }     // 내부 중복 로직 분리
```

:::info
인터페이스 타입으로 구현체를 참조하면 VMI가 자연스럽게 동작한다.

네스티드 인터페이스: 인터페이스 안에 인터페이스를 두는 방식 — 역할 계층화 목적.
구현 시 `Outer.Inner` 형태로 내부 타입 지정.
:::

**핵심 키워드:** `static final` `default메소드` `implements` `네스티드인터페이스` `이너클래스`

## 오늘의 핵심 요약

1. 달력 로직: 월 인덱스는 반드시 `-1` 보정, 이전 달 1월 예외 처리 필수
2. `Calendar` = 월 0부터, `LocalDate` = 월 1부터 — Java 8 이상이면 `LocalDate` 권장
3. 오버로딩 = 인자 시그니처로 구분 / 오버라이딩 = 상속 관계에서 재정의
4. VMI = 참조 타입으로 노출 범위 제한 + 실제 객체 타입으로 메소드 실행
5. `this()` = 생성자 체이닝, `super()` = 부모 생성자 호출
6. 인터페이스는 다중 구현 가능, 클래스 다중 상속은 불가
