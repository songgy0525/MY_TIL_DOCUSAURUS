🗺 오늘 배운 흐름 한눈에 보기​

로컬에서 개발한 앱을 실제 서버에 올려서 외부에서 접근 가능하게 만드는 전체 흐름을 실습했다.

OS 준비 → Java 설치 → Tomcat 10 → systemd 등록 → Jenkins CI/CD
(Ubuntu 22.04)  (OpenJDK 21)  (WAR 배포)  (자동 기동)   (자동화)

1️⃣ 서버 구축 기반 — OS와 SSH​

서버는 로컬 IDE 실행과 다르다. 외부 사용자가 접근 가능한 환경이 돼야 하기 때문에 OS 설치, 네트워크, 권한 관리가 전부 엮여있다.

:::info 클라우드 vs 온프레미스 AWS, Azure 같은 클라우드는 인프라(IaaS)를 빌리는 것. 보안 요구가 높은 기업은 직접 서버를 구축하는 온프레미스를 선택하기도 한다. 오늘 실습은 로컬 PC를 서버처럼 써서 온프레미스 흐름을 경험하는 방식이었다. :::

SSH 키 기반 인증​

ID/PW 방식보다 키 기반 인증이 안전하다. 공개키는 서버에, 개인키는 클라이언트에 보관한다.

단계명령어목적
키 생성ssh-keygen -t rsa -b 4096공개키/개인키 쌍 생성
키 위치~/.ssh/id_rsa.pub공개키 서버에 등록
PPK 변환PuTTYgenPuTTY 접속용 변환

핵심 키워드: IaaS 온프레미스 LTS CLI SSH

2️⃣ OpenJDK 21 설치와 환경변수​

오라클 JDK는 기업 환경에서 유료(코어당 과금)가 될 수 있어서 OpenJDK를 쓰는 게 일반적이다. Spring Boot 3.x는 Java 17 이상을 요구하는 경우가 많아서 21 LTS를 선택했다.

# 패키지 목록 업데이트 후 설치
apt update && apt upgrade
apt install openjdk-21-jdk

# 설치 확인
java -version
find / -name java

환경변수 설정 — /etc/profile vs /etc/environment​

파일목적형식
/etc/profile쉘 시작 시 전역 설정export 사용, PATH 확장에 적합
/etc/environment시스템 전역 변수 선언export 없이 KEY="VALUE"
# 설정 즉시 반영
source /etc/profile
source /etc/environment

# 적용 확인
echo $JAVA_HOME

핵심 키워드: OpenJDK JAVA_HOME PATH source Vim

3️⃣ Tomcat 10 수동 설치와 WAR 배포​

apt로 설치 가능한 버전과 실제 필요한 버전이 다를 수 있어서, 실무에서는 tar.gz로 직접 설치한다.

설치 절차​

  1. wget으로 tar.gz 다운로드 후 /tmp에 압축 해제
  2. /usr/local/tomcat10으로 이동 (실행파일은 /usr 계열)
  3. chmod -R 755으로 하위까지 실행 권한 부여
  4. CATALINA_HOME 환경변수 설정
  5. tomcat-users.xml에서 관리자 계정 추가
  6. context.xml에서 RemoteAddrValve 주석 처리 (외부 접근 허용)
경고

context.xml의 RemoteAddrValve 제한 해제는 보안상 민감한 설정이다. 실무에서는 IP 제한을 유지하고 허용 대상을 최소화하는 게 일반적이다.

# 기동 / 종료
./bin/startup.sh
./bin/shutdown.sh

# 기동 확인
curl http://localhost:8080

핵심 키워드: Tomcat CATALINA_HOME tomcat-users.xml context.xml WAR

4️⃣ systemd로 Tomcat 서비스 등록​

수동 실행은 서버 재부팅 후 매번 사람이 기동해야 해서 운영에 부적합하다. systemd에 등록하면 부팅 시 자동 기동된다.

서비스 전용 계정 만들기​

# 그룹 및 nologin 계정 생성
groupadd tomcat
useradd -s /bin/nologin -g tomcat -d /usr/local/tomcat10 tomcat

# 소유권 이전 (chmod: 권한비트 변경 / chown: 소유자 변경)
chown -PR tomcat:tomcat /usr/local/tomcat10
정보

nologin 계정은 대화형 로그인이 불가능한 서비스 전용 계정이다. 보안을 위해 서비스는 전용 계정으로 실행한다.

서비스 파일 핵심 구성​

항목의미
User, Group서비스 실행 계정/그룹 (tomcat)
EnvironmentJAVA_HOME, CATALINA_HOME 경로
ExecStart/ExecStop기동/종료 스크립트 연결
WantedBymulti-user.target (부팅 단계 연결)
# 서비스 등록 및 관리
systemctl daemon-reload
systemctl enable tomcat10.service
systemctl start tomcat10.service
systemctl status tomcat10.service

# 포트 점유 확인 (-l 리스닝 -n 숫자 -t TCP -p 프로세스)
ss -lntp

핵심 키워드: systemd systemctl useradd chown ss

5️⃣ Jenkins 설치와 포트 충돌 해결​

Jenkins는 Git push 이벤트를 받아 소스 체크아웃 → 빌드 → 배포를 자동화하는 CI 서버다. 설치 후 Tomcat(8080)과 포트 충돌이 발생해서 8181로 변경했다.

Git push → (webhook) → Jenkins → (Maven 빌드) → WAR 생성 → Tomcat 배포 → 서비스

포트 충돌 해결 포인트​

:::danger 핵심 /etc/default/jenkins와 systemd 서비스 파일 두 곳 모두 포트를 일치시켜야 한다. 한 곳만 바꾸면 적용이 안 된다. :::

# 두 곳 다 8181로 변경 필요
# 1. /etc/default/jenkins → HTTP_PORT=8181
# 2. jenkins.service → JENKINS_PORT=8181

systemctl daemon-reload
systemctl start jenkins
systemctl status jenkins

Jenkins 초기 설정 순서​

  1. http://localhost:8181 접속
  2. cat <initialAdminPassword 경로> 로 초기 비번 확인
  3. Install suggested plugins 선택
  4. 관리자 계정 생성 (꼭 해야 이후 설정이 편함)

핵심 키워드: Jenkins CI 포트 충돌 systemd GitHub Actions

[TIL] Java final과 상속, 재정의

2026년 2월 27일 · 약 3분

부트캠프 백엔드 과정 · 2026.02.27

오늘 배운 흐름 한눈에 보기​

Eclipse 프로젝트 관리 → final 변수 → final 메소드 → final 클래스

1. Eclipse 프로젝트 & 코드 관리​

프로젝트가 많아지면 탐색기가 복잡해지고 메모리도 점유되므로, 사용하지 않는 프로젝트는 닫아두는 것이 좋다.

작업경로효과
프로젝트 닫기우클릭 → Close Project비활성화, 메모리 절약
닫힌 프로젝트 숨기기탐색기(점 3개) → Filters → Closed Projects 체크목록에서 안 보임
다시 열기탐색기에서 더블클릭재활성화

코드 포맷팅​

우클릭 → Source → Format
단축키: Ctrl + Shift + F

팀 단위 개발에서 포맷 미적용 코드는 리뷰 품질을 저하시키므로 습관화가 필요하다.

핵심 키워드: Eclipse Close Project Filters Format 메모리 관리

2. final의 3가지 적용 지점​

final은 "어디에 붙이느냐"에 따라 제약 대상이 달라진다.

적용 대상final 의미핵심 효과
변수상수화최초 1회만 값 결정, 재대입 불가
메소드재정의(override) 불가자식 클래스가 구현을 바꿀 수 없음
클래스상속 불가extends로 확장 불가
정보
  • 확장(extends): 부모 기능을 물려받아 범위를 넓히는 것
  • 재정의(override): 부모의 동작을 자식이 동일한 시그니처로 바꿔 끼우는 것

final은 이 두 가능성을 명시적으로 차단한다.

핵심 키워드: final 변수 메소드 클래스 상속

3. final 변수 — 초기화와 재대입 금지​

final 변수는 단 한 번만 값을 결정할 수 있다. 이후 재대입 시 컴파일 오류 발생.

변수 종류별 정리​

변수 종류선언 위치접근/특징
인스턴스 변수클래스 내부(필드)객체를 통해 접근, 생성 시 초기화
지역 변수(로컬)메소드 내부메소드 밖에서 직접 접근 불가, return으로 전달
정적 변수(static)클래스 내부(필드)클래스명으로 접근, 메모리에 1회 로딩 후 공유

코드 예시​

public class FinalClass {
    public static final int AGE = 10;  // 선언과 동시에 초기화

    public static final int[] ARR;
    static {
        ARR = new int[3];  // 정적 초기화 블록에서 초기화
    }
}
final int a = 10;
a = 20;  // 컴파일 오류 — 이미 값이 지정됨
경고

멤버필드에 final을 선언하면 반드시 선언 시점 또는 정적 초기화 블록(static {})에서 값을 채워야 한다. 비어있으면 컴파일 오류.

핵심 키워드: 상수 초기화 static 블록 로컬 변수 재대입

4. final 메소드 — 오버라이드 차단​

부모 메소드가 final이면 자식 클래스에서 재정의할 수 없다. 호출을 통한 사용만 허용된다.

부모 메소드 상태Override 목록 노출자식 재정의 가능 여부
일반 메소드노출됨가능
final 메소드노출 안 됨불가
String msg = child.callMessage();  // 반환값은 변수에 받거나 출력 함수로 전달해야 함
System.out.println(msg);
정보

반환 타입이 있는 메소드는 호출만 한다고 출력이 자동으로 발생하지 않는다. 반환값을 사용하려면 반드시 변수에 받거나 출력 함수로 전달해야 한다.

핵심 키워드: override final 메소드 상속 반환 타입 Source 메뉴

5. final 클래스 — 상속 금지​

final 클래스는 다른 클래스의 부모가 될 수 없다.

final class X {}
class Y extends X {}  // 컴파일 오류

대표 사례: String 클래스는 final로 선언되어 있어 상속이 불가하다. 문자열 동작을 임의로 변형하는 상황을 방지하기 위한 설계다.

구분의미
final 클래스확장 구조 고정 — 상속 불가
final 메소드동작 고정 — 재정의 불가
final 변수값 고정 — 재대입 불가

핵심 키워드: final 클래스 String 타입 안정성 상속 금지 불변성

오늘의 핵심 요약​

  1. Eclipse 프로젝트 많아지면 Close Project + Filters로 관리
  2. 코드 포맷팅 단축키: Ctrl + Shift + F
  3. final 변수 = 재대입 불가, 반드시 초기화 필요
  4. final 메소드 = 자식이 override 불가, 사용만 가능
  5. final 클래스 = extends 불가 (대표 사례: String)
  6. 반환값 있는 메소드는 변수에 받거나 출력 함수로 전달해야 함

1️⃣ 문자, 유니코드와 형변환, 문자열 결합​

char는 내부적으로 유니코드 코드값(정수) 으로 저장된다.

char n = '9';
char m = '0';
int result = n - m;                // 57 - 48 = 9 (코드값끼리 연산)
System.out.println("결과: " + result);

System.out.println((char)result);  // 코드값 9 → 탭/제어문자처럼 보일 수 있음
정보

'9' - '0' = 9 (문자끼리 뺄셈처럼 보이지만 실제로는 정수 코드값 연산)

+ 연산자가 문자열과 만나면 다른 피연산자도 문자열로 변환해서 이어 붙인다 → 컨캐트네이션(concatenation)

경고

유니코드 표의 모든 값이 눈에 보이는 문자는 아니다. 코드값 13 = 엔터(제어문자) → 출력 시 공백처럼 보일 수 있음

핵심 키워드: 유니코드 char 명시적형변환 컨캐트네이션 정수연산

2️⃣ if 조건문과 Scanner 입력 처리​

형태목적특징

if-else참/거짓 양분반드시 하나는 실행

Scanner — 콘솔 입력 처리​

import java.util.Scanner;

Scanner scan = new Scanner(System.in);
System.out.print("정수 값을 입력해 주세요: ");
int input = scan.nextInt();
System.out.println("입력받은 정수값: " + input);
정보

import는 다른 패키지에 있는 클래스를 현재 파일에서 사용하겠다는 명시다. 같은 이름의 클래스가 다른 패키지에 존재할 수 있어서 패키지 경로로 구분한다.

경고

콘솔이 빨간색으로 실행 중 → 입력 대기 상태일 수 있음

nextInt()에 문자(한글 등)를 입력하면 → InputMismatchException 발생

핵심 키워드: if문 else if Scanner import InputMismatchException

3️⃣ switch 문 — 전통 ~ Java 14+​

switch는 범위 비교(<, >)가 아닌 값의 동일성 기반 선택문이다.

범위 조건 → if / 개별 값 매핑 → switch

전통 switch (~ Java 13)​

switch (n) {
    case 0:
        System.out.println("0이다.");
        break;
    case 1:
        System.out.println("1이다.");
        break;
    default:
        System.out.println("다른 값이다.");
}
위험

break 빠뜨리면 fall-through 발생 → 아래 case까지 연쇄 실행됨

Java 14+ switch expression​

// arrow label (break 불필요, 여러 case 콤마로 묶기 가능)
String result = switch (key) {
    case 1 -> "하나";
    case 2, 3 -> "둘 또는 셋";
    default -> "다른 숫자";
};

// yield — 블록 내 추가 로직 후 값 반환
String result2 = switch (key) {
    case 1 -> "하나";
    default -> {
        String msg = "알 수 없음: " + key;
        yield msg;  // 블록의 최종 반환값
    }
};
버전/문법핵심 변화주의점
전통 switchbreak로 종료누락 시 fall-through
Java 7+String 비교 가능비교값은 입력 타입과 같아야 함
Java 14+ expression결과를 변수에 대입 가능구조 규칙 준수 필요
arrow labelbreak 없이 단일 동작여러 case 콤마로 묶기 가능
yield블록 내 로직 후 값 반환중괄호로 감싸야 함

핵심 키워드: switch fall-through switch expression arrow label yield

4️⃣ for 반복문과 스코프​

실행 순서​

초기화 → 조건검사 → 본문 → 증감 → 조건검사 → 본문 → ...
정보

i < 5 처럼 미만 조건이면 마지막 값(5)은 본문이 실행되지 않는다.

처음 접할 때는 디버그 표로 변수값 / 조건 결과 / 출력 / 증감을 단계별로 적어보면 이해가 빨라진다.

스코프 주의​

// i를 반복문 밖에서 쓰고 싶다면 밖에 선언해야 함
int i = 0;
for (; i < 5; i++) {
    System.out.println(i);
}
System.out.println("마지막 i: " + i);  // 5

핵심 키워드: for문 스코프 누적변수 모듈러스 진약수

5️⃣ 누적 합과 진약수 합​

누적 합 패턴​

int sum = 0;
for (int i = 0; i < 5; i++) {
    sum += i;  // 0+1+2+3+4
}
System.out.println("합: " + sum);  // 10

진약수 합 (자기 자신 제외한 약수의 합)​

int n = 10;
int sumResult = 0;

for (int i = 1; i < n; i++) {   // 자기 자신 제외
    if (n % i == 0) {           // 나누어 떨어지면 약수
        sumResult += i;         // 누적
    }
}
System.out.println(n + "의 진약수의 합: " + sumResult);  // 8 (1+2+5)
정보

약수 판별 = 모듈러스(%)로 나머지가 0인지 확인

이 패턴은 완전수, 친화수 같은 문제로 확장되는 전형적인 누적 변수 패턴이다.

2️⃣ JAR 패키징과 Runnable JAR 실행​

JAR(Java Archive)는 소스가 아닌 실행/배포를 위해 결과물을 묶는 패키징 산출물이다.

  4. Destination 경로/파일명 지정 후 Finish

java -jar 파일명.jar

연산자동작

6️⃣ JAVA_HOME 환경변수 설정​

JAVA_HOME은 자바 기반 소프트웨어가 JDK 위치를 공통 참조하는 표준 환경변수다.

echo %JAVA_HOME%
경고
  • 값은 JDK 루트 폴더까지만 (bin 포함 ❌)
  • 시스템 변수로 설정해야 전체 계정/프로세스에 적용됨
  • 설정 후 CMD를 새로 열어야 반영됨

핵심 키워드: JAVA_HOME 시스템변수 echo CMD 표준환경

7️⃣ PATH 환경변수 설정과 검증​

Path 시스템 변수에 %JAVA_HOME%\bin 추가 → 어디서든 java 명령 실행 가능

java -version

자주 겪는 문제

증상원인조치

echo %JAVA_HOME%이 문자열 그대로 출력환경변수 미적용시스템 변수 재등록 후 창 모두 닫고 CMD 재실행
Mac에서 확인 방법 다름Unix 계열은 $VAR 표기echo $JAVA_HOME 으로 확인

핵심 키워드: PATH 우선순위 java -version 중복JDK CLI

9️⃣ 자바 기본 구조와 실행 흐름​

요소의미핵심 규칙
클래스값/기능의 묶음, 타입이 됨public 클래스명 = 파일명 일치
메소드기능의 단위, 호출로 실행반환 타입 있으면 return 필요

정보

자바는 컴파일 언어 — 메소드 정의 순서는 실행과 무관하다. HTML처럼 위에서 아래로 즉시 해석되는 인터프리터 방식과 다르다.

핵심 키워드: main메소드 클래스명규칙 컴파일 System.out.println API

🔟 변수, 타입, 대입, 인스턴스화​

int n = 10;           // 대입: 오른쪽 값을 왼쪽 변수에 저장
String s = "hello";   // 참조 타입
Coffee c = new Coffee(); // 인스턴스화: 클래스를 메모리에 올려 객체 생성
  • 기본 타입: 언어가 미리 정의한 타입 (int, char, boolean 등)
  • 참조 타입: new 등으로 생성되는 복합 구조
  • 오류(빨간 줄) = 문법/타입/세미콜론/반환 등 규칙 위반 → 반드시 해결 후 진행

핵심 키워드: 변수 데이터타입 대입연산자 new 인스턴스화

1️⃣2️⃣ 접근 제어자​

제어자접근 범위한 줄 정리
public전체 공개모든 패키지/클래스에서 접근 가능
private내부 전용선언한 클래스 내부에서만 접근 가능
protected상속 범위자식 클래스에서 접근 가능
default패키지 범위같은 패키지 소속에서만 접근 가능
정보

모든 자바 클래스는 기본적으로 extends Object를 포함한다. 자동완성에서 보이는 notify, hashCode 등은 Object로부터 상속된 기능이다.

핵심 키워드: public private protected default 패키지

1️⃣3️⃣ 파라미터 vs 아규먼트​

void order(int money) {  // money는 파라미터
    System.out.println(money);
}
order(100);  // 100은 아규먼트
  • 파라미터: 메소드 선언부의 입력 변수
  • 아규먼트: 호출 시 실제로 전달하는 값

✅ 오늘의 핵심 요약​

  1. JDK는 Amazon Corretto 21 LTS, 공백 없는 경로에 수동 설치
