[TIL] Git 협업, Docker, 클라우드 기초

2026년 5월 22일

부트캠프 백엔드 과정 · 2026.05.22

1. Git 팀 협업 시나리오​

형상관리자: 저장소 생성 → 초기 템플릿 push → 브랜치 생성 → 팀원 초대
                                                              ↓
팀원: 클론 → 자기 브랜치에서 작업 → commit → push → PR 생성
                                                    ↓
형상관리자: PR 검토 → main 머지
                         ↓
팀원 전원: pull로 최신화 후 다음 작업 시작

pull 없이 작업 시작 = 충돌의 씨앗

역할 구분​

역할주요 작업
형상관리자저장소 생성, 머지, 규칙 수립, .gitignore 배포
개발자자기 브랜치에서만 작업, 머지 후 pull 필수

핵심 키워드: #Repository #Branch #Pull Request #Merge #Sync

2. 커밋 메시지 규칙​

# 타입 기반 커밋 메시지
git commit -m "feat: 차량 목록 조회 API 추가"
git commit -m "fix: 로그인 NPE 수정"
git commit -m "docs: README 업데이트"
git commit -m "refactor: 서비스 계층 분리"
타입의미
feat기능 추가
fix버그 수정
docs문서 변경
refactor리팩터링

3. .gitignore 필수 항목​

# 빌드 산출물
target/
*.class

# 로그/임시파일
*.log
*.tmp

# IDE 설정
.settings/
.project
.classpath

# 프론트 의존성
node_modules/
dist/

gitignore.io = 기술 스택 입력하면 자동 생성

협업 전제조건​

인코딩: 모든 팀원 UTF-8 통일 (Eclipse: Preferences → Content Types)
.gitignore: 형상관리자가 초기에 표준으로 배포
머지: 형상관리자만 수행
최신화: 머지 완료 후 전원 pull

4. 컴플릭트(충돌) 해결​

원인: 동일 파일의 같은 줄을 서로 다르게 수정 후 병합

GitHub PR → "Resolve conflicts" 클릭
충돌 마커 수정:
<<<<<<< 내 브랜치
int a = 1;
=======
int a = 2;
>>>>>>> main
           ↓
하나만 남기고 마커 제거
           ↓
"Mark as resolved" → "Commit merge"

충돌 예방 = 규칙 수립이 최우선 / 발생 시 합의로 해결

5. 클라우드 서비스 모델​

모델의미관리 주체
SaaS완성 소프트웨어 서비스제공자 전담
PaaS실행 플랫폼 서비스플랫폼만 제공자, 앱은 개발자
IaaS인프라(서버) 서비스인프라만 제공자, OS부터 개발자

배포 모델​

모델특징
퍼블릭 클라우드빠른 확장, 보안 이슈 존재
프라이빗 클라우드보안 강함, 구축/운영 부담 큼
하이브리드민감 데이터 = 프라이빗, 나머지 = 퍼블릭
멀티 클라우드여러 퍼블릭 클라우드 혼용

6. VM vs 컨테이너 (도커)​

VM:
물리 서버 → 하이퍼바이저 → 게스트 OS × N → 앱
→ 각 VM이 OS 전체 포함 → 무거움

도커 컨테이너:
물리 서버 → 호스트 OS → 도커 엔진 → 컨테이너 × N
→ OS 없이 필요한 실행 환경만 → 가벼움

핵심 용어​

용어의미
Image실행 환경 설계도 (CD에 비유)
Container이미지를 실행한 인스턴스
Docker Hub이미지 공유 저장소
Kubernetes다수 컨테이너 자동 관리/분배

핵심 키워드: #VM #컨테이너 #Docker Image #Docker Hub #Kubernetes

오늘의 핵심 요약​

  1. Git 협업 = 브랜치 분리 + 머지 후 전원 pull 필수
  2. 형상관리자 = 저장소 생성, 머지, 규칙 수립 담당
  3. 커밋 메시지 = 타입: 요약 형태로 의도 명확히
  4. .gitignore = target/, node_modules/ 반드시 포함
  5. 인코딩 UTF-8 통일 = 협업에서 가장 먼저 맞춰야 함
  6. 충돌 = 마커 구간에서 올바른 코드 선택 후 마커 제거
  7. SaaS = 완성 소프트웨어 / PaaS = 플랫폼 / IaaS = 인프라
  8. 하이브리드 클라우드 = 보안 민감도에 따라 분리 운영
  9. VM = 게스트 OS 포함 → 무거움 / 도커 = OS 없이 → 가벼움
  10. 컨테이너 = 이미지의 실행 인스턴스, 이미지 = 설계도
