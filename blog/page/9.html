오늘 배운 흐름 한눈에 보기​

Eclipse 프로젝트 관리 → final 변수 → final 메소드 → final 클래스

1. Eclipse 프로젝트 & 코드 관리​

프로젝트가 많아지면 탐색기가 복잡해지고 메모리도 점유되므로, 사용하지 않는 프로젝트는 닫아두는 것이 좋다.

작업경로효과
프로젝트 닫기우클릭 → Close Project비활성화, 메모리 절약
닫힌 프로젝트 숨기기탐색기(점 3개) → Filters → Closed Projects 체크목록에서 안 보임
다시 열기탐색기에서 더블클릭재활성화

코드 포맷팅​

우클릭 → Source → Format
단축키: Ctrl + Shift + F

팀 단위 개발에서 포맷 미적용 코드는 리뷰 품질을 저하시키므로 습관화가 필요하다.

핵심 키워드: Eclipse Close Project Filters Format 메모리 관리

2. final의 3가지 적용 지점​

final은 "어디에 붙이느냐"에 따라 제약 대상이 달라진다.

적용 대상final 의미핵심 효과
변수상수화최초 1회만 값 결정, 재대입 불가
메소드재정의(override) 불가자식 클래스가 구현을 바꿀 수 없음
클래스상속 불가extends로 확장 불가
정보
  • 확장(extends): 부모 기능을 물려받아 범위를 넓히는 것
  • 재정의(override): 부모의 동작을 자식이 동일한 시그니처로 바꿔 끼우는 것

final은 이 두 가능성을 명시적으로 차단한다.

핵심 키워드: final 변수 메소드 클래스 상속

3. final 변수 — 초기화와 재대입 금지​

final 변수는 단 한 번만 값을 결정할 수 있다. 이후 재대입 시 컴파일 오류 발생.

변수 종류별 정리​

변수 종류선언 위치접근/특징
인스턴스 변수클래스 내부(필드)객체를 통해 접근, 생성 시 초기화
지역 변수(로컬)메소드 내부메소드 밖에서 직접 접근 불가, return으로 전달
정적 변수(static)클래스 내부(필드)클래스명으로 접근, 메모리에 1회 로딩 후 공유

코드 예시​

public class FinalClass {
    public static final int AGE = 10;  // 선언과 동시에 초기화

    public static final int[] ARR;
    static {
        ARR = new int[3];  // 정적 초기화 블록에서 초기화
    }
}
final int a = 10;
a = 20;  // 컴파일 오류 — 이미 값이 지정됨
경고

멤버필드에 final을 선언하면 반드시 선언 시점 또는 정적 초기화 블록(static {})에서 값을 채워야 한다. 비어있으면 컴파일 오류.

핵심 키워드: 상수 초기화 static 블록 로컬 변수 재대입

4. final 메소드 — 오버라이드 차단​

부모 메소드가 final이면 자식 클래스에서 재정의할 수 없다. 호출을 통한 사용만 허용된다.

부모 메소드 상태Override 목록 노출자식 재정의 가능 여부
일반 메소드노출됨가능
final 메소드노출 안 됨불가
String msg = child.callMessage();  // 반환값은 변수에 받거나 출력 함수로 전달해야 함
System.out.println(msg);
정보

반환 타입이 있는 메소드는 호출만 한다고 출력이 자동으로 발생하지 않는다. 반환값을 사용하려면 반드시 변수에 받거나 출력 함수로 전달해야 한다.

핵심 키워드: override final 메소드 상속 반환 타입 Source 메뉴

5. final 클래스 — 상속 금지​

final 클래스는 다른 클래스의 부모가 될 수 없다.

final class X {}
class Y extends X {}  // 컴파일 오류

대표 사례: String 클래스는 final로 선언되어 있어 상속이 불가하다. 문자열 동작을 임의로 변형하는 상황을 방지하기 위한 설계다.

구분의미
final 클래스확장 구조 고정 — 상속 불가
final 메소드동작 고정 — 재정의 불가
final 변수값 고정 — 재대입 불가

핵심 키워드: final 클래스 String 타입 안정성 상속 금지 불변성

오늘의 핵심 요약​

  1. Eclipse 프로젝트 많아지면 Close Project + Filters로 관리
  2. 코드 포맷팅 단축키: Ctrl + Shift + F
  3. final 변수 = 재대입 불가, 반드시 초기화 필요
  4. final 메소드 = 자식이 override 불가, 사용만 가능
  5. final 클래스 = extends 불가 (대표 사례: String)
  6. 반환값 있는 메소드는 변수에 받거나 출력 함수로 전달해야 함

1️⃣ 문자, 유니코드와 형변환, 문자열 결합​

char는 내부적으로 유니코드 코드값(정수) 으로 저장된다.

char n = '9';
char m = '0';
int result = n - m;                // 57 - 48 = 9 (코드값끼리 연산)
System.out.println("결과: " + result);

System.out.println((char)result);  // 코드값 9 → 탭/제어문자처럼 보일 수 있음
정보

'9' - '0' = 9 (문자끼리 뺄셈처럼 보이지만 실제로는 정수 코드값 연산)

+ 연산자가 문자열과 만나면 다른 피연산자도 문자열로 변환해서 이어 붙인다 → 컨캐트네이션(concatenation)

경고

유니코드 표의 모든 값이 눈에 보이는 문자는 아니다. 코드값 13 = 엔터(제어문자) → 출력 시 공백처럼 보일 수 있음

2️⃣ if 조건문과 Scanner 입력 처리​

if / else if / else​

형태목적특징

Scanner — 콘솔 입력 처리​

import java.util.Scanner;

Scanner scan = new Scanner(System.in);
System.out.print("정수 값을 입력해 주세요: ");
int input = scan.nextInt();
System.out.println("입력받은 정수값: " + input);
정보

경고

3️⃣ switch 문 — 전통 ~ Java 14+​

switch는 범위 비교(<, >)가 아닌 값의 동일성 기반 선택문이다.

범위 조건 → if / 개별 값 매핑 → switch

전통 switch (~ Java 13)​

switch (n) {
    case 0:
        System.out.println("0이다.");
        break;
    case 1:
        System.out.println("1이다.");
        break;
    default:
        System.out.println("다른 값이다.");
}
위험

break 빠뜨리면 fall-through 발생 → 아래 case까지 연쇄 실행됨

Java 14+ switch expression​

// arrow label (break 불필요, 여러 case 콤마로 묶기 가능)
String result = switch (key) {
    case 1 -> "하나";
    case 2, 3 -> "둘 또는 셋";
    default -> "다른 숫자";
};

// yield — 블록 내 추가 로직 후 값 반환
String result2 = switch (key) {
    case 1 -> "하나";
    default -> {
        String msg = "알 수 없음: " + key;
        yield msg;  // 블록의 최종 반환값
    }
};
버전/문법핵심 변화주의점
전통 switchbreak로 종료누락 시 fall-through
Java 7+String 비교 가능비교값은 입력 타입과 같아야 함
Java 14+ expression결과를 변수에 대입 가능구조 규칙 준수 필요
arrow labelbreak 없이 단일 동작여러 case 콤마로 묶기 가능
yield블록 내 로직 후 값 반환중괄호로 감싸야 함

핵심 키워드: switch fall-through switch expression arrow label yield

4️⃣ for 반복문과 스코프​

실행 순서​

초기화 → 조건검사 → 본문 → 증감 → 조건검사 → 본문 → ...
정보

i < 5 처럼 미만 조건이면 마지막 값(5)은 본문이 실행되지 않는다.

처음 접할 때는 디버그 표로 변수값 / 조건 결과 / 출력 / 증감을 단계별로 적어보면 이해가 빨라진다.

스코프 주의​

// i를 반복문 밖에서 쓰고 싶다면 밖에 선언해야 함
int i = 0;
for (; i < 5; i++) {
    System.out.println(i);
}
System.out.println("마지막 i: " + i);  // 5

핵심 키워드: for문 스코프 누적변수 모듈러스 진약수

5️⃣ 누적 합과 진약수 합​

누적 합 패턴​

int sum = 0;
for (int i = 0; i < 5; i++) {
    sum += i;  // 0+1+2+3+4
}
System.out.println("합: " + sum);  // 10

진약수 합 (자기 자신 제외한 약수의 합)​

int n = 10;
int sumResult = 0;

for (int i = 1; i < n; i++) {   // 자기 자신 제외
    if (n % i == 0) {           // 나누어 떨어지면 약수
        sumResult += i;         // 누적
    }
}
System.out.println(n + "의 진약수의 합: " + sumResult);  // 8 (1+2+5)
정보

약수 판별 = 모듈러스(%)로 나머지가 0인지 확인

이 패턴은 완전수, 친화수 같은 문제로 확장되는 전형적인 누적 변수 패턴이다.

2️⃣ JAR 패키징과 Runnable JAR 실행​

JAR(Java Archive)는 소스가 아닌 실행/배포를 위해 결과물을 묶는 패키징 산출물이다.

형식용도
JAR일반 자바 앱 배포
WAR웹 앱 배포 (서블릿 컨테이너 필요)
Spring Boot JAR내장 서버 포함, 단독 실행 가능

Runnable JAR 생성 순서​

  1. Java Project 생성 후 패키지(3단위 이상) + 메인 클래스 생성
  2. Run As > Java Application 으로 한 번 실행 (Launch configuration 등록)
  3. 프로젝트 우클릭 → Export > Runnable JAR file 선택
  4. Destination 경로/파일명 지정 후 Finish
  5. 터미널에서 실행
java -jar 파일명.jar
정보

터미널 명령어 차이:

  • Windows CMD: DIR
  • Linux/Mac 터미널: ls

핵심 키워드: JAR Runnable JAR Manifest Export java -jar

3️⃣ 기본 타입(Primitive)과 리터럴​

정수 리터럴 표기법​

표기예시의미

4️⃣ 실수(부동소수점)와 캐스팅​

float에 실수 리터럴 대입 시 기본이 double이라 오류 발생 → F 접미사 또는 명시적 캐스팅 필요

float f1 = 3.14F;          // F 접미사
float f2 = (float) 3.14;   // 명시적 캐스팅
double d1 = 3.14;
double d2 = 3e2;           // 지수 표기법: 3 × 10² = 300.0
정보

연산 결과는 참여하는 타입 중 더 큰 타입으로 승격된다. 금융 도메인 등 정밀도가 중요한 곳에서는 타입 선택과 오차 관리가 핵심이다.

핵심 키워드: 부동소수점 float double 캐스팅 지수표기법

  • 연산에 참여하면 정수로 승격 → 다시 문자로 바꾸려면 캐스팅 필요

// boolean b = 1;  ← 자바에서는 불가! (다른 언어와 다름)

구분선언 위치자동 초기화접근 방식
로컬 변수메소드 내부❌ (미초기화 시 컴파일 오류)메소드 내부에서만 사용
인스턴스 변수멤버필드✅ (타입 기본값)obj.field

위험

핵심 키워드: 로컬변수 인스턴스변수 static this 스코프

8️⃣ DTO와 단일 반환​

자바는 반환값이 1개만 가능 → 여러 값을 반환해야 할 때 DTO를 사용한다.

    return dto;
}

9️⃣ 연산자 총정리​

산술 연산 주의점​

int result = 5 / 2;       // 2 (정수끼리 나누면 몫만)
float f = 5 / 2;          // 2.0 (연산은 정수, 저장만 float)
float f2 = 5 / 2.0F;      // 2.5 (실수가 참여해야 실수 결과)
long l = 10L;             // L 접미사 = long 리터럴

대입 연산 주의​

i += 5;   // 올바른 단축 대입
i =+ 5;   // 주의! 양수 표시로 해석됨 (+=와 다름)

비트 연산​

5 & 4   // 0101 & 0100 = 0100 = 4
5 | 4   // 0101 | 0100 = 0101 = 5

숏서킷 (Short-circuit)​

연산자동작
&&앞이 false면 뒤 평가 생략
||앞이 true면 뒤 평가 생략
&, |앞 결과 무관하게 뒤까지 모두 평가
정보

연산자 우선순위 — 전체 암기보다 괄호가 최우선이라는 원칙만 기억하자.

IDE의 노란 언더라인은 컴파일 오류가 아닌 품질 경고 (사용 안 된 변수, 무의미한 표현 등)

핵심 키워드: 모듈러스 캐스팅 증감연산자 비트연산 숏서킷

🔟 char → 숫자 변환​

char c = '9';

int wrong = (int) c;              // 57 (유니코드 코드포인트)
int correct1 = c - '0';           // 9 ('0' 코드포인트를 빼면 실제 숫자)
int correct2 = Character.getNumericValue(c);  // 9 (API 활용)
정보

'9'를 int로 캐스팅하면 57 (유니코드 코드포인트)이 나온다.

실제 숫자 값을 얻으려면 - '0' 또는 Character.getNumericValue() 사용!

핵심 키워드: char 캐스팅 유니코드 Character.getNumericValue 리터럴 타입연산

  7. &&/|| = 숏서킷, &/| = 전체 평가

한국 환경에서 EUC-KR이 언급될 수 있지만, 협업/배포/다국어 환경에서는 UTF-8이 표준이다.

핵심 키워드: 주석 예약어 UTF-8 EUC-KR 인코딩

✅ 오늘의 핵심 요약​

  1. JDK는 Amazon Corretto 21 LTS, 공백 없는 경로에 수동 설치
  2. JAVA_HOME → JDK 루트 경로 (bin 미포함), 시스템 변수로 설정
  3. PATH → %JAVA_HOME%\bin 추가, 기존 JDK 경로 중복 주의
  4. Eclipse는 Package(압축) 방식, eclipse.ini에서 JDK 명시 연결
  5. 자바는 파일명 = 클래스명, main이 없으면 실행 불가
  6. new = 인스턴스화, . = 멤버 접근, = = 오른쪽 값을 왼쪽에 저장
  7. AI 쓸 때는 주제 분리 + 역할 부여 먼저

운영 항목기준주의점

3️⃣ QR 출결 체계​

출결은 머사A 앱에서 QR 체크 + 강의실 입장 두 가지를 모두 완료해야 한다.

:::danger 중요 "체크 완료" 문구가 떠도 실제 시간이 기록됐는지 반드시 확인! 전산 오류로 누락되는 사례가 있고, 미확인은 본인 부주의로 처리된다. :::

항목시간 창비고
입실 QR08:50 ~ 09:10창 외에는 멘토에게 요청
퇴실 QR17:50 ~ 18:30수업 지연 고려해 길게 열림
상시 QR고정 창 외요청방 양식으로 신청
위험

해외에서 QR 출석 = 부정 출결 = 즉시 제적 (청강은 가능하지만 QR 체크는 절대 안 됨)

핵심 키워드: QR체크 강의실입장 입퇴실시간확인 상시QR 해외출석금지

4️⃣ 지각 / 조퇴 / 외출 / 결석 규칙​

핵심: 50% 규칙​

하루 수업의 50% 미만 수강 = 결석 처리된다.

구분인정 조건주의점
결석QR 미체크 or 50% 미만 수강일부 참여해도 결석 될 수 있음
지각시작 후 50% 이내 입실QR만 찍고 입실 늦으면 지각
조퇴50% 이상 수강 후 중간 퇴실50% 미만이면 결석 처리
외출외출 QR → 복귀 QR 절차 완료두 QR 모두 찍어야 함

누적 규칙​

경고

지각 + 조퇴 + 외출 각각 3회 누적 = 결석 1회

하루에 지각 + 외출 + 조퇴 모두 하면 → 하루에 3회 누적 가능

핵심 키워드: 50%규칙 지각 조퇴 외출 누적3회결석

공결 가능 사유​

초반에 경미한 사유로 소진하면 나중에 못 씀 — 전략적으로 사용할 것

증빙 서류 요건​

공결 유형필수 서류핵심 요건
질병/입원진료확인서 + 처방전 + 결제영수증질병코드 기재 필수

6️⃣ 수강 장소 규정​

오전/오후 QR은 동일한 장소에서 찍는 게 원칙. 불가피하게 이동할 경우 장소 이동 확인서 사전 제출 필수.

공간 유형가능 여부이유
1인 룸카페 / 1인 스터디룸✅ 조건부 가능소음 통제, 단독 공간
독서실✅ 비교적 가능고정 좌석, 저소음
도서관⚠️ 지양오픈 공간, 이동 인원 노출
일반 카페/음식점❌ 불가에 가까움부정 출결 판단 가능성 큼
경고

장소 이동은 쉬는 시간 / 점심시간에만 가능. 수업 중 이동 = 무단이탈

핵심 키워드: 장소이동확인서 쉬는시간이동 오픈공간제한 부정출결 수강환경

부정 출결은 횟수 무관 즉시 제적
